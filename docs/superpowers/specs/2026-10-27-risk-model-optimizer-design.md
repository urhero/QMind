## 1. 왜 만드는가

### 지금 흐름
1. QMind `mp` 가 롱숏 배포 북(MP)을 만든다. 노출은 `data/MXWO/mp_target_gross.csv` 일정 (2026-09-30 부터 롱 +16% / 숏 -16%).
2. 사용자가 **목표 포트 = BM + MP** 를 bbg 에 올린다. 숏이 BM 비중보다 큰 종목은 목표 비중이 음수다.
3. bbg PORT 옵티마이저가 bbg 리스크 모델로 "목표 대비 TE 최소 + 롱온리" 포트를 찾고, 그대로 매매한다 → 실제 AP.

### 빈틈
- **백테스트는 MP 를 그대로 들고 있다고 가정한다.** 실제 AP 는 음수 비중을 0 에서 막고, 옵티마이저가 비슷하게 움직이는 다른 종목으로 그 자리를 메운 결과다. 이 차이는 한 번도 측정된 적이 없다.
- 차이가 작지 않을 수 있다는 근거: 같은 제약을 "그냥 잘라내는" 방식(`bm_short_cap`, 2026-08-21)으로 흉내 냈을 때 Sharpe +0.715 → -0.447 로 뒤집혔다 (숏 북이 대형주로 쏠림). 반면 bbg 옵티마이저는 위험 구조를 보고 대체하므로 목표 대비 ex-ante TE 가 ~15bp 수준(기존 메모)이다. **"잘라내기"와 "위험 인지 대체" 사이 어디쯤이 진짜 성과인지 모른다.**
- 성과분석도 bbg 에만 의존한다. 10월 모멘텀 반전 손실처럼 "명시적 모멘텀 3% 인데 MP 전체로는 모멘텀에 기울어 있던" 숨은 노출을 사내에서 정량화할 도구가 없다.

### 최종 목표 (사용자 결정)
사내 리스크 모델 + 옵티마이저가 **bbg 옵티마이저를 대체해 실제 매매 비중을 산출**한다.
같은 엔진이 백테스트 안에서도 돌아 "구현 가능한 AP 성과"를 보여 주고, 같은 리스크 모델로 위험·성과를 분해한다.

## 2. 성공 기준

사용자 기준: **"bbg 와 매매 비중이 비슷하게 나오고, 성과분석도 비슷하게 되면 충분."**

→ 그래서 목표는 "우리 나름의 좋은 리스크 모델"이 아니라 **bbg MAC3 를 최대한 닮은 모델**이다.
완전 동일은 불가능하다 (bbg 의 ESTU 1만+ 종목, 내부 데이터, 비공개 파라미터). "비슷하다"의 수치 기준은 아래와 같다.
**수치는 설계자 제안이며, 첫 비교(Phase 3) 결과를 보고 사용자와 다시 정한다.**

| # | 항목 | 비교 방법 | 기준 (제안) |
|---|---|---|---|
| S1 | 목표 추종 품질 | 같은 목표·초기 포트·제약에서, **bbg 모델로 잰 bbg 목적함수값**(Active Total Risk + Currency, §4) 비율: 우리 AP / bbg AP. TE 만 따로도 보고 | ≤ 1.15 |
| S2 | 비중 근접 | bbg 모델로 잰 TE(우리 AP vs bbg AP) | 보고만 (S1 이 상한을 정한다 — 아래) |
| S3 | 비중 근접 (참고) | 편도 차이 Σ\|w_ours - w_bbg\|/2 | 보고만 (첫 비교 후 기준 설정) |
| S4 | 스타일 노출 | BM 구성종목 기준 우리 vs bbg 노출의 횡단면 상관 (스타일별, 지역별로도 — Integrated 는 지역 모델 안에서 표준화). 종목별 노출을 PORT 에서 못 내보내면 여러 시험 포트의 포트 단위 노출 비교로 바꾼다 (Phase 0 확인) | ≥ 0.9 |
| S5 | ex-ante TE 수준 | MP·AP 의 TE: 우리 / bbg | 0.8 ~ 1.25 |
| S6 | Brinson 성과분석 | 월별 총 배분·총 선택 효과: 우리 vs PORT (같은 보유, **PORT 와 같은 bbg 일별 수익률**) | 차이 ≤ 1bp |
| S7 | 팩터 성과분석 | 월별 팩터 그룹(스타일/업종/국가/통화/고유) 기여: 우리 vs PORT FBA | 차이 ≤ max(3bp, PORT 값의 20%); 부호 일치는 \|PORT\| ≥ 5bp 인 달만 (0 근처 부호는 잡음) |

S1 이 가장 중요하다: 운용 목적은 "목표에 가깝게 따라가기"이고, TE 최소화 해는 서로 다른 비중 조합이 거의 같은 TE 를 낼 수 있어서 비중 자체(S3)보다 추종 품질(S1)이 본질이다.

**S1 과 S2 의 관계 (리뷰 2026-10-28):** bbg AP 는 bbg 모델에서 최적이므로, 같은 제약을 지키는 우리 AP 와의 차이 d 에 대해 TE(우리→목표)² ≥ TE(bbg→목표)² + TE(d)² 가 성립한다 (최적점의 1차 조건; 통화 항·정수 제약 때문에 근사). 그래서 S1 비율이 r 이면 TE(d) ≤ √(r²−1) × TE(bbg→목표) — r = 1.15 면 0.57 배다. 지금 AP 의 목표 대비 TE 가 ~15bp(사용자 메모)이므로 S1 통과는 TE(d) ≤ ~8.5bp 를 뜻한다. 이전 초안의 S2 ≤ 5bp 는 r ≤ 1.05 와 같아 S1 보다 훨씬 엄격하고 둘이 맞지 않았다 → S2 는 관문에서 빼고 보고만 한다.

**S1 을 목적함수값으로 재는 이유:** bbg 는 TE 와 통화 위험의 합을 최소화한다. TE 만 비교하면 통화 위험을 더 진 우리 해가 비율 1 미만으로 보여 좋아 보일 수 있다.

백서로 확인한 의미:
- 여러 목적은 `Σ (목적값 / trade-off)` 를 최소화한다. Active Total Risk = sqrt((w-wb)'Q(w-wb)) (분산이 아니라 표준편차).
- "Currency" 는 통화 팩터 그룹의 액티브 위험으로 해석한다 (**가정** — Phase 0 에서 PORT 도움말/수치로 확인).

- 최소 거래 크기와 lot 은 비볼록(정수) 제약이라 bbg 는 혼합정수 탐색을 쓴다.
- 운용 수치 (사용자 메모): 목표의 BM 대비 ex-ante TE ~0.65% (배수로 수동 조절), AP 의 목표 대비 ex-ante TE ~15bp.

## 5. 설계

### 5.1 리스크 모델 구조 — MAC3 Global Equity 모델을 따른다

MAC3 공통 골격 (Methodology Notes 기준):
- 종목 로컬 초과수익 = 시장 + 국가 + 업종 + 스타일 + 고유. 통화는 별도 명시적 팩터(FX 수익률).
- 팩터 수익률: **일별** 횡단면 가중회귀. 제약 = 업종 팩터 수익률의 시총가중 합 0, 국가 팩터도 동일 → 시장 팩터 = 시총가중 시장 수익률.
- 회귀 가중치 = 잔차분산의 역수 (전통적 sqrt(시총) 대신).
- 스타일 노출: 극단값 2단계 절단(robust → 일반 표준편차) → 시총가중 평균 0, 동일가중 표준편차 1. 결측 펀더멘털은 업종 평균으로.
- 업종·국가 노출은 0/1 대신 시계열 베타(업종/국가 대비, 0.4~2.0 근처로 절단, 시총가중 평균 1). 신규 상장은 1 로 수축.
- 업종 = BICS 기반 56개 (Global 모델 표 1.2 — BICS 코드 매핑이 백서에 있음). 국가 = Country of Risk.
- 14개 스타일: Beta, Residual Volatility, Momentum, Size, Mid-cap, Earnings Yield, Valuation, Dividend Yield, Long-Term Reversal, Liquidity, Growth, Variability, Profit, Leverage.

### 5.2 옵티마이저 — bbg 설정 재현

```
변수: w (종목 비중, 거래 유니버스), c (현금)
a = w - w_target                       # 목표(BM+MP) 대비 액티브
minimize  sqrt(a' Q a) + sqrt(a' Q_ccy a)     # trade-off 1:1, Q_ccy = 통화 블록만
s.t.      w >= 0, 1'w + c = 1, 0 <= c <= 0.002
          w_i = 0 (유니버스 밖, 단 초기 보유는 매도만 허용)
```
- Q 는 USD 기준: 종목 USD 수익 = 로컬 수익 + 환율 수익 → Q = [노출|통화노출] × (주식+통화 팩터 공분산) × [...]' + 고유분산.
- 팩터 형태 그대로 2차 원뿔(SOCP)로 푼다 (N×N 공분산을 만들지 않음). 솔버: `cvxpy` (+ Clarabel/OSQP) — **새 의존성 1개** (`Pipfile [packages]` 에 추가 — CI 가 Pipfile 을 직접 파싱해 설치). scipy 로는 1,500 변수 + 등식제약 SOCP 가 느리고 불안정.
- 최소 거래 0.01%: 연속해 → |거래| < 1bp 종목은 초기 비중으로 고정 → 재풀이, 변화 없을 때까지 (최대 몇 회). bbg 의 혼합정수 해와 미세하게 다를 수 있음 → S2 로 영향 확인.
- 1주 단위: 프로덕션에서만 (NAV·가격 필요). 백테스트에서는 생략.
- 목표에 있지만 거래 유니버스 밖인 종목(음수 비중과 마찬가지로 도달 불가)은 그대로 목표에 남겨 둔다 — 옵티마이저가 상관 종목으로 대체하는 것이 bbg 와 같은 동작.

### 5.3 백테스트 통합

- 붙일 자리: `service/backtest/stock_level.py:build_stock_series` — 이미 `benchmark` 인자로 BM 숏 상한(`apply_bm_short_cap`)을 거는 훅이 있다. 같은 자리에 **선택형 AP 옵티마이저 경로**를 추가한다 (기본 off → 기존 산출물 불변).
- 매월 t: 목표 = BM_t + MP_t(배수·섹터캡 적용 후) → 초기 = 전월 AP 를 수익률로 드리프트 → 그 시점까지 데이터로 만든 리스크 모델로 최적화 → AP_t.
- AP 의 액티브 = AP_t - BM_t. 수익 = 액티브 × 수익률 (기존 오버레이 회계와 같은 틀).
- 비용 = **액티브 북 변화분** 기준 (BM 자체 재구성 매매는 인덱스 운용에서도 생기는 비용이라 제외) — 기존 MP 비용 회계와 일관 (설계자 판단).
- 산출: 기존 `stock_level_series` 에 AP 열을 추가하거나 별도 CSV — MP 성과 vs AP 성과 vs (참고) 잘라내기 방식, 그리고 차이(구현 손실) 시계열.
- 백테스트 BM 은 MXWO (`msci_idx_wgt` 990100 `basis='N'`, §5.5 — 기존 `bmwgt.parquet`·`MXWO_WGT` 는 대조·키 연결용). 프로덕션 BM 은 M1CXKICI = MXWO − KIC 금지 종목·국가 (2026-07 기준 차이 0개). 백테스트의 거래 유니버스는 KIC 제외 이력이 없으므로 MXWO 전체로 둔다 (§8 Q10).
- 리스크 모델은 매월말 시점 재추정 (PIT). OOS 100개월(2018-06~2026-09) × 1회 최적화 — 계산량 부담 없음.
- 첫 달 초기 포트 = BM (인덱스에서 출발). 이후는 전월 AP 드리프트.
- MP 경로는 운용 동등 기준(`--factor-rebal-months 1`)으로 비교한다 (2026-10-21 B안 재검증 원칙). 결과는 `docs/experiments/_TEMPLATE.md` 형식으로 기록.

### 5.4 성과분석

| 산출 | 내용 | 대응 bbg |
|---|---|---|
| ex-ante 위험 분해 | MP·AP 의 TE 를 스타일/업종/국가/통화/고유로 분해, 팩터별 액티브 노출(σ 단위) | PORT Risk / Tracking Error 탭 |
| ex-post 팩터 기여 | 일별: Σ 액티브노출 × 팩터수익 + 고유. 기간 연결은 PORT 설정(산술/기하 Carino)에 맞춤 | MAC HPA Factor-Based (FBA) |
| Brinson | GICS 섹터 단일 레벨, 상대(relative) 방식: 배분 = 액티브 섹터비중 × (BM 섹터수익 - BM 전체수익), 선택 = 포트 섹터비중 기준 (interaction 없음) — prove-out 엑셀 수식과 동일 | MAC HPA Total Return (Relative; Single-Level) |

- 일별 수익률은 기존 MTD 캐시(`data/{BENCHMARK}/daily_ret/`)를 재사용, 기존 MTD 대시보드/원페이저에 탭·섹션으로 붙인다 (새 리포트 체계를 만들지 않는다). PORT 와 같은 bbg 수익률이라 S6·S7 대조에 맞다. 단 이 캐시에는 미국 종목인데 로컬≠USD 수익률인 9건(2026-09, 예 PEP)이 있어 S6 전에 원인을 확인한다. 과거 구간(백테스트 AP)은 리스크 모델과 같은 MSCI·AA 수익률을 쓴다.
- PORT 와 대조(S6·S7)할 때는 **같은 보유내역**(PORT 에서 내보낸 AP 보유)을 입력으로 쓴다 — 보유가 다르면 방법론 차이와 섞여 비교가 안 된다.
- 10월 사례 같은 질문("모멘텀 때문에 얼마 잃었나")에 바로 답하는 것이 1차 사용처.

### 5.5 데이터 수집·관리 (2026-10-27 추가 설계)

요약: **팩터값(노출)은 월말이면 충분하고, 일별이 필요한 건 수익률뿐이다.** 일별 수익률의 용도는 세 가지다.
① 매일 팩터 수익률 회귀 → 공분산 (월간이면 135개 관측으로 항목 ~110개의 상관을 추정해야 해서 사실상 불가),
② 베타·잔차변동성·모멘텀·장기반전처럼 가격에서 나오는 노출 계산 (월 1회 계산, 재료가 일별 — 첫 노출일보다 최대 4년 앞선 이력 필요),
③ 일별 성과분석 (2026-09 이후는 이미 캐시 있음).

#### 원칙
1. **원천(raw)과 파생을 나눈다.** 원천 = 외부에서 받은 그대로 (수익률, FX, 분류 스냅샷, 식별자). 파생 = 노출·팩터수익·공분산 — 언제든 원천에서 다시 계산할 수 있으므로 캐시일 뿐이다.
   git: 원천 추출본은 넣지 않고, **파생은 리스크 모델 브랜치 `risk_model` 에서 일단 커밋한다** (2026-10-30 사용자 결정 — `.gitignore` 예외 `!data/*/risk/`, `!data/*/classification.parquet`).
2. **주 원천은 사내 DB** — MSCIDB(2017-06~)와 GLOBAL `AA_market`(~2017-05) (2026-10-27~28 확인, 아래). bbg API 는 세 곳만 메운다: 2015-06~2017-04 일별 환율, MSCIDB 가 통째로 빠진 5일, (필요 시) 편입 전 이력. 원천 추출본은 git 에 넣지 않는다 (용량 + 벤더 데이터 재배포 금지; 기존 `.gitignore` 의 `data/*/*` 기본 제외). MSCIDB 에서 언제든 다시 뽑을 수 있으므로 별도 백업은 필수가 아니다.
3. **기본 키는 `gvkeyiid`** (ClariFI 키). MSCIDB 는 ISIN 으로 연결한다 (MSCI 보안코드 `msci_security_code` 는 매핑 테이블에 보관).
4. **파일 형식은 기존 관례**: 일별 데이터는 월 단위 parquet, 작은 참조 테이블은 csv.
5. **적재는 여러 번 돌려도 안전하게**(멱등): 매 실행이 "없는 월만" 뽑고, 최근 2개월은 다시 뽑아 덮어쓴다 (벤더 사후 정정 반영).

확인 결과:

- **검증 (2026-10-28, 일별 단위). 직접 겹치는 기간은 18영업일뿐이라, 같은 출처(bbg)인 `BB_market` 을 다리로 써서 2년을 검증했다:**
  - **2년 대조 — `BB_market`(bbg) vs MSCIDB, 2017-06~2019-04, 선진국 1,702종목 × 495일 = 68만 종목-일: 99.74% 가 1bp 이내.** 반기별 99.59~99.97% 로 안정. 날짜를 하루 밀면 0.9% → 날짜 정렬 정확. 비교 가능 비중은 MSCI 선진국 시총의 92~96% (2019 년은 비미국이 끊겨 58%).
    - 국가별 1bp 이내: 미국 99.90, 영국 99.93, 캐나다 99.99, 독일 100.00, 프랑스 99.54, 일본 99.60, 호주 99.36, 이스라엘 82.4 (%).
    - 남는 차이의 원인: **일본** — 99% 가 배당락일, 배당을 반영하는 날짜가 다름 (bbg 는 절반이 배당락일에 배당을 안 넣음; 크기 중앙 12bp, 연 단위로는 상쇄). **호주** — 96% 가 배당락일, bbg 가 97% 높음 (중앙 62bp; 프랭킹 크레딧(법인세 공제분) 포함 여부 차이로 추정) → 2017-06 이전 호주 종목 총수익률이 배당락일마다 약간 높게 들어간다. **미국** — 0.09%, 대부분 분할 상장(DLPH·DOV·ALV 등) 처리 차이. **이스라엘** — 일요일 거래일 날짜 관행 차이.
    - 월 누적(그 달 내내 있는 종목만, MSCI 가 하루 통째로 빠진 2017-08·2018-12 제외): 97.3% 가 1bp 이내 — 미국 99.72, 영국·캐나다·프랑스·독일·스위스·스웨덴 98.6~100, 일본 91.2, 호주 87.1 (%) — 일별 결과와 같은 원인.

- 종목 키는 bbg 티커 (거래소 코드 포함, `Equity` 없음, 예 `AAPL UW`). MXWD 월말 구성종목 중 티커로 바로 찾아지는 비율 (BM 비중 기준): 2008 94.1%, 2010 96.3%, 2012 97.4%, 2014 98.4%, 2015 99.4%, 2016 99.5%. 못 찾은 것은 주로 티커가 바뀐 종목 (예 `UBSN VX`, `IMT LN`, `GSZ FP`) — MSCIDB 월말 테이블의 시점별 `bb_ticker ↔ isin` 으로 매핑하면 대부분 풀릴 것으로 본다 (Phase 1 에서 실측).
- **주의 1 — 티커 재사용.** 키가 "그때의 티커"가 아니라 적재 시점 티커라, 티커가 다른 회사로 넘어간 경우 다른 회사의 이력이 붙어 있다 (실측: `CB UN` 2015 년 = 옛 Chubb 자리에 ACE 이력, `UA UN` 2016 클래스 분할). → 매핑 검증 규칙 (식별자 매핑 절 참조).
- **주의 2 — 중간 끊김.** 2,141개 id 가 2016-01-21, 4,214개가 2016-12-30 에 끊긴다 (적재 대상 축소로 보임). MXWO 종목은 대부분 이어지지만 일부(예 `TYC UN`)는 끊겨 있다 — 위 완결성 98.7% 에 이미 반영된 수치.
- **아직 못 한 것:** DB ISIN 이 최신값이라 그 사이 ISIN 이 바뀐 종목(BM 비중 7~11%: GE·Shell·GSK·Novo·RTX·Booking 등)은 이번 검증에서 매핑되지 않았다. `msci_security_code` 이력으로 매핑 (Phase 1 에서 실측).
- 같은 DB 의 `BB_market` (bbg 일별 가격·총수익률)은 미국·중국·홍콩 위주이고 2019~2021 에 갱신이 끊겨 쓰지 않는다.

MSCI 는 WM/Reuters 런던 16시 고시를 쓴다. MSCIDB 일별 환율은 2017-04-28 부터라, 그 전 일별은 MSCI 와 가장 비슷한 bbg 티커를 찾아 채운다.

- **후보 비교:** 선진국 통화 13개 × 후보 18종 (`X Curncy`(뉴욕 종가), `CMPL/CMPN/CMPT`, `BGNL`, BFIX `F100~F230`) 을 2017-05~2019-04 MSCI 일별 환율과 2년간 비교.
- **결과: BFIX `F110` (뉴욕 11:00 = 런던 16:00) 이 1위**, 단 미국·영국 서머타임이 어긋나는 연 3주쯤(런던 16시 = 뉴욕 12시)은 `F120` 이 맞다. 둘을 날짜별로 고른 **'런던 16시' 합성 시계열이 13개 통화 모두 1위**: 수준 차이 중앙 0.13~1.6bp, 일별 변화 차이 RMS 0.5~3.9bp (평균 2.5bp; 일별 환율 변동 50~70bp 대비 무시할 수준).
- **월말은 MSCI 값으로 고정:** MSCI 월말 환율(`M_DAILY_TRACKER_XRATES`, 1997~; 일별 테이블과 겹치는 457일 값이 완전히 같음)이 빈 구간에도 있다. 월말에 비율 log(MSCI/bbg)를 맞추고 월중은 선형 보간해 곱한다. 일별 겹침 구간에서 시험하면 월 변화 오차 최대 7.0 → 2.3bp, 일별 오차는 그대로 2.5bp.
- **빈 구간 자체 검증 (월말 24개):** 앵커 전 bbg 런던 16시 vs MSCI 월말 — 수준 차 중앙 2.4bp, 월 변화 차 RMS 5.9bp (겹침 구간의 약 2배). 앵커를 걸면 월말은 0.
- 위안화(MXCN1A)는 어느 후보도 잘 맞지 않는다 (최선 `CNY CMPT` 일별 RMS 11bp). Phase 7 에서 따로 본다.

#### 수정가격 문제 — 가격을 저장하지 않는다
- 수익률은 MSCI 가 계산한 **일별 총수익률(`gross_return_loc`)** 을 쓴다. MSCI 가 분할·무상증자·배당을 반영해 계산한 값이라 **수정주가 + 배당 재투자와 같은 결과**다. 2017-06 이전은 GLOBAL `AA_market` 의 `art` (같은 값, 실측 일치).
  - 예: 1:2 액면분할 날, 원주가는 100 → 50 으로 -50% 처럼 보이지만 총수익률은 0% 다. 배당락일에 주가가 배당만큼 빠져도 총수익률은 배당을 더해 준다.
- 가격이 필요한 곳은 따로 처리한다.
  - 시가총액(회귀 가중·표준화): ClariFI `LogMktCap` 월말 PIT 값 (원주가 × 주식수 — 수정가격을 쓰면 오히려 틀림).
  - 회전율·Amihud: ClariFI `STO`, `Amihud`.
  - 1주 단위 반올림(프로덕션): 그날의 실제 가격 1회 조회. 저장 불필요.
- 통화: 리스크 모델은 **로컬 수익률과 환율을 따로** 쓴다 — USD 수익률 = (1+로컬)×(1+환율)-1 이라 둘을 갖고 있으면 USD 는 계산되고, 주식 위험과 통화 위험을 나눠야 옵티마이저의 "통화 위험 최소화" 목적과 성과분석의 통화 기여를 계산할 수 있다. 환율은 MSCIDB `DAILY_TRACKER_XRATES` (MSCI 지수·DB `mreturn` 과 같은 환율).
- 배당은 세전(gross) 기준이다. MSCI Net(원천징수 후)도 MSCIDB 에 있으므로 성과분석 대조(S6·S7)에서 PORT 기준에 맞춰 고를 수 있다.
- **확인 (2026-10-27 실측): DB `mreturn` = MSCI USD 가격수익률, 배당 미포함.** 미국 종목 7개(배당락 있는 NLY·PEP·O·VICI 포함)에서 bbg 배당 미조정 가격수익률과 일치하고 (예: NLY 9/30 배당락 $0.75 — DB -17.58%, 가격 -17.58%, 총수익 -14.42%), MSCIDB `price_return_usd` 월 누적과 중앙값 1.1bp 차이. 리스크 모델은 총수익률을 쓰므로 영향 없음. **기존 백테스트는 배당이 빠진 수익률로 돌고 있다** — 롱숏 오버레이라 (롱 배당수익률 - 숏 배당수익률) × 노출만큼 성과가 빠져 있다. MSCIDB `gross_return_usd` (2017-06~) 와 `AA_market` `art` × MSCI 환율 (2015-06~2017-05) 로 보정 가능. 별도 과제.
- **bbg API 주의:** `HistoricalDataRequest` 는 기본으로 단말기 DPDF 설정을 따르는데, 이 단말기는 `PX_LAST` 를 **배당(정상·특별) 조정**해서 준다 (실측). 가격을 받는 코드는 `adjustmentFollowDPDF=False` 와 조정 플래그를 항상 명시한다.

#### 식별자 매핑
- DB 의 `isin` 은 이력이 없다 (실측: 2,397종목 모두 136개월 내내 ISIN 하나 = 최신값). `gvkeyiid → ISIN → msci_security_code` 로 연결하되, MSCIDB 쪽 ISIN 은 날짜별 값이므로 **그 종목이 한 번이라도 가졌던 ISIN** 으로 매칭하고 `msci_security_code` 단위로 이력을 잇는다 (ISIN 이 바뀐 종목 대응; `SECURITY_CODE_MAP` 의 `isin_next_day` 로 변경 추적).
- **매핑 검증:** MSCIDB `price_return_usd` 월 누적 = DB `mreturn` 이어야 한다 (실측 중앙값 1.1bp). 종목별로 어긋나면 매핑 오류로 본다 — bbg 때보다 훨씬 강한 검증이다.
- 매핑 실패 종목은 제외하되 **BM 비중 기준 제외 비율**을 매월 리포트한다 (2017-06 이후 ISIN 기준 0~0.8%. 2017-06 이전은 ISIN 이 바뀐 종목 때문에 아직 7~11% — `msci_security_code` 이력 매핑 후 다시 잰다).
- 2017-06 이전 `AA_market` 은 bbg 티커가 키라 MSCIDB 월말 테이블의 시점별 `bb_ticker → isin` 으로 잇는다. bbg FIGI 매핑은 전혀 필요 없다.
- **이어 붙인 곳 검증:** 2017-06 겹침 구간에서 종목별 `art` 와 `gross_return_loc` 차이 > 2bp 목록을 리포트한다 (매핑 오류 탐지).
- **2017-06 이전 종목-월 검증:** `AA_market` 월누적 × MSCI 월말 환율 - DB `mreturn` 이 **-50bp** 보다 작으면 (배당 몫은 + 쪽이므로 큰 음수는 오류 신호) 그 종목-월을 쓰지 않고, 3개월 이상 걸리는 종목은 매핑 자체를 다시 본다 — 티커 재사용, 다른 상장 라인(예 HSBC 가 `5 HK` 로 매핑), 월중 끊김을 잡는다. 임계 실측 (2015-07~2017-05, 온전한 종목-월 3.3만 개): -10bp 면 1.46% 가 걸리는데 대부분 2016-07 의 DB 환율 차이(엔·호주·캐나다 −24~−28bp)라 오탐이고, -50bp 면 0.05% 이면서 알려진 매핑 오류(`5 HK` −354, `UA UN` −403, `CB UN` −2,371bp)는 모두 잡힌다.

#### 분류 이력 (GICS·BICS 가 중간에 바뀌는 문제)

GICS 는 8자리 코드 하나에 4단계가 다 들어 있다 — 2자리 섹터(11) / 4자리 산업그룹(25) / 6자리 산업(74) / 8자리 세부산업(163) (MSCI GICS Methodology 2024-08). **8자리 코드의 월별 이력만 있으면 모든 단계의 PIT 이력이 나온다.**

실측 사실 (2026-10-27):
- **DB 의 GICS 섹터 이름은 시점별(PIT)로 저장돼 있다.** 11년간 섹터 변경 257건 = 체계 개편 196건 (2016-09 부동산 분리 106, 2018-10 커뮤니케이션 신설 65, 2023-03 개편 25) + 회사 사유 61건 (56종목, 전체 2,400의 ~2%).
- ClariFI DB(kb_global)에는 GICS 코드가 없다 (`sec` = 섹터 이름뿐).
- **bbg Desktop API 는 분류 과거값을 주지 않는다** (BICS·GICS 섹터 = "Not valid historical field", GICS 하위 = 빈 응답).
- **MSCIDB 에 GICS 8자리 PIT 이력이 있다**: `SECURITY_REPORT.sub_industry` 일별 (2017-06~), `M_SECURITY_REPORT.sub_industry` 월말 (1997~); GLOBAL `AA_idxmbr` 에도 MXWD 월말 GICS 8자리 (2003~), 변경 이벤트는 `DAILY_FILE_RIF` (변경 전·후 코드).

**결정: GICS 이력은 MSCIDB 에서 만든다.** ClariFI DB 에 코드를 추가할 필요 없음 (§8 Q9 해소). 2017-06 이전은 월말 테이블, 이후는 일별 테이블.

저장: `classification.parquet` 에 `gvkeyiid, gics8, valid_from, valid_to` — 값이 바뀐 날만 행을 만든 이력 테이블. 상위 단계는 코드 앞자리로 계산한다.

**체계 개편 정규화 (리스크 모델 전용, 리뷰 2026-10-28 수정):** PIT 코드를 그대로 쓰면 2018-10·2023-03 같은 개편 때 업종 팩터가 생기거나 사라져 팩터 수익률 이력이 끊긴다 (예: 2018 년 이전에는 "Interactive Media & Services" 산업이 없다). 이전 초안은 "개편으로 바뀐 종목의 과거 이력을 개편 후 코드로 덮어쓴다"였는데, **이건 개편 발표 전 시점의 백테스트에 미래 분류를 넣는 것**이라 반목표(미래 정보)에 걸린다. 그래서 **추정 시점 t 에 유효한 체계로 t 까지의 이력을 맞춘다**: t 가 개편 전이면 옛 체계 그대로, 개편 후면 개편으로 바뀐 종목만 과거 이력을 새 코드로 바꿔 회귀를 다시 돌린다 (개편은 11년에 3번이라 이력 재계산도 3번). 회사 사유 변경(~2%)은 언제나 그 시점 값 그대로. 개편일 목록은 MSCI 발표 기준으로 고정 (2016-09, 2018-09/10, 2023-03 등 — 빌더가 MSCI 공지로 확정).

| 용도 | 분류 | 이력 기준 |
|---|---|---|
| 리스크 모델 업종 팩터 | GICS 6자리 산업 (얇은 산업은 병합) | PIT + 체계 개편 정규화 |
| Brinson 섹터 효과 | GICS 2자리 섹터 | PIT 그대로 (개편 시점 포함 — PORT 도 당시 분류로 계산) |
| (예비) BICS | 리스크 모델 업종을 BICS 로 바꿀 때만 | 현재값 소급 + 그때부터 매월 스냅샷 |

#### 적재 절차

MSCIDB 는 사내 DB 라 bbg 사용량 한도가 없다. 연결 정보는 `config.py` 에 MSCIDB 서버·DB 이름을 추가하고 계정은 기존 `.env` 의 것을 쓴다 (GLOBAL·MSCIDB 모두 `10.206.1.119,9433`).

**1회 추출 (Phase 1)** — 몇 분~수십 분
1. `SECURITY_REPORT` 를 월 단위로 뽑아 `msci/daily/YYYY-MM.parquet` 저장 (DM+EM 전체를 저장하고 유니버스 필터는 읽을 때 — MXCN1A 도 같은 파일 사용).
2. GLOBAL `AA_market` `art` 2011-07~2017-05 → `global/aa_daily/` (1회로 끝).
3. `M_SECURITY_REPORT` (2011~), `DAILY_TRACKER_XRATES` (2017-04-28~) + 2015-06~2017-04 환율 채우기 (1회), 배당 파일. MSCIDB 가 통째로 빠진 5일(2017-08-01~03, 2018-12-31, 2019-12-31)은 bbg `DAY_TO_DAY_TOT_RETURN_GROSS_DVDS` 로 채운다 (`BB_market` 또는 API, 정의 같음 — 위 2년 검증).
4. `gvkeyiid ↔ msci_security_code ↔ bb_ticker` 매핑 → `mreturn` 대조·2017-06 이음매 검증 → 실패 리포트.
5. GICS 이력 → `classification.parquet`.
6. 품질 리포트 → 통과하면 Phase 2.

**매월 갱신** (기존 `download --incremental` 다음 단계로)
1. 지난달 + 그 전달 `SECURITY_REPORT`·환율 재추출 (덮어쓰기 — 벤더 정정 반영).
2. 신규 편입 종목 매핑, GICS 바뀐 종목만 이력에 추가.
3. 품질 리포트 → 리스크 모델 그 달 추정 → (운용 전환 후) `frozen/` 에 사본.

#### 품질 점검 (매 적재 후 자동 리포트)
- 커버리지: 날짜별로 수익률이 있는 종목의 **BM 비중 합** (목표 99% 이상).
- 이상치: 일별 |수익률| > 50% 목록 (기업행위 오류 의심).
- 정지: 5거래일 이상 연속 0 수익률.
- 빈 날: 날짜별 DM 종목 수가 직전 21일 중앙값의 절반 이하인 날, 종목 단위로 처음~마지막 등장 사이에 빠진 날.
- 매핑: MSCIDB 가격수익률 월 누적 vs DB `mreturn` (종목별 차이 > 50bp 목록).
- 분류: 이번 달 바뀐 종목 목록.

### 5.6 코드 배치

- 새 패키지 `service/risk/` — 리스크 모델(노출·팩터수익·공분산), 옵티마이저, 성과분석. 파일은 최소로.
- 프로덕션 전환 전까지 `mp` 파이프라인과 기존 백테스트 기본 경로는 건드리지 않는다 (byte-identical 검증 A/B 그대로 통과).
- 리스크 모델 산출물(노출·팩터수익·공분산·고유위험)은 월별 parquet 로 캐시 (`data/{BENCHMARK}/risk/` — 빌더가 경로 확정).
- 검증 스크립트·bbg 대조는 `research/` 에.

## 6. 단계

각 단계는 끝에 확인 관문이 있다. 관문을 못 넘으면 다음 단계로 가지 않고 원인을 먼저 본다.
단, **0단계(사용자, bbg)와 1단계(데이터)는 동시에 진행한다** — 1~2단계는 bbg 자료가 필요 없고, 0단계 결과는 3단계부터 쓴다.

| 단계 | 내용 | 산출 | 관문 |
|---|---|---|---|
| **0. 정답지 확보** (사용자 + 설계자) | **먼저 확인할 것 3가지:** (가) 옵티마이저 Bmrk 에 목표 포트가 들어가는지 (§4), (나) "Currency" 목적의 정의, (다) 종목별 MAC3 노출을 PORT 에서 내보낼 수 있는지 (안 되면 S4 를 포트 단위로 바꾼다). 그다음 PORT 에서 비교 자료 내보내기: ① 최근 몇 달의 목표 포트·초기 포트·옵티마이저 결과 ② 같은 날짜의 종목별 MAC3 노출 ③ 목표/AP 의 ex-ante TE 와 분해 ④ 같은 기간 성과분석(Brinson, FBA). 가능하면 PORT 옵티마이저 **Backtest 기능**(월간 최대 120회, 과거 목표 포트를 날짜별로 BBU 업로드)으로 bbg AP 이력도 생성 — **이것만으로 "백테스트에 옵티마이저 미반영" 문제의 1차 답(구현 손실 크기)이 코드 없이 나온다** | `data/MXWO/bbg/` (`.gitignore` 의 `data/*/*` 로 무시됨 — `TEMP/` 는 무시 대상이 아니라 커밋 사고 위험) | 비교에 쓸 최소 1개월 세트 확보 |

## 8. 사용자 확인이 필요한 것

답변 완료 (2026-10-27):

  후속 실험 후보: MAC3 에 없는 우리 고유 성격(Analyst Expectations 등)을 **고정 정의** 팩터 1~2개로 덧붙여 Phase 4 백테스트에서 A 와 비교.
