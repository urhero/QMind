- 판정: **수정 채택** (사용자 결정). 다음 `mp` 회차부터 적용. 이미 배포한 9/30 북은 그대로 둔다

## 문제

백테스트 행 t 는 val(t-1) 순위로 월 t 수익을 번다. 그런데 `mp` 는 기준일 T 북(월 T+1 보유)을 `filtered_data` 의 T 행 라벨, 즉 **val(T-1) 순위**로 만들었다.
10월에 들고 있는 9/30 북이 8/31 값 순위인 셈이라 백테스트보다 신호가 한 달 늦었다.

확인: 커밋된 북의 전 팩터 L/S 를 각 시점 값으로 재현한 불일치율.

| 북 | val(T-1) 기준 | val(T) 기준 |
|---|---|---|
| MXCN1A 9/30 / 8/31 | 0.10% / 1.08% | 8.34% / 18.29% |
| MXWO 9/30 / 8/31 | 0.05% / 0.07% | 5.35% / 11.40% |

시점 정의 확인: `PM1M`(1개월 수익률) 순위상관은 전월 수익 0.04, 같은 달 수익 0.93, 다음달 수익 -0.02 (718708 2023~). `ddt=T` 값은 T 말 정보이고 백테스트에 미래 정보는 없다.

## 수정 (3가지)

| 차이 | 백테스트 | 수정 전 `mp` | 수정 |
|---|---|---|---|
| 북 라벨 시점 | 월 t 수익 = val(t-1) 순위 | T 북 = val(T-1) 순위 | `label_book_at_date`: val(T) 순위, 규칙은 학습 결과 그대로 매핑 |
| 선정·가중 입력 비용 | 종목비용 x 0.6 | 종목비용 전액 | `selection_cost_bps` 공유 |
| IS 마지막 달 비용 | 다음 달 목표까지 보고 계상 | 0 | 기준일 북을 다음 달 행으로 붙여 계상 |

규칙 학습 주기(백테스트 기본 6개월, `mp` 매달)는 이 수정에 포함되지 않는다.

## 수정 후 `mp` = 백테스트 대조

기준일까지만 데이터를 잘라 `mp` 를 돌리고 직전 선정만 백테스트 이력으로 넣은 뒤, 팩터 비중과 "북 x 다음 달 수익" 을 비교.

- **expanding IS:** 3개 시점(2022-05, 2025-11, 2026-08) 선정 일치. 718708 비중 차이 최대 0.0004%p, 수익 차이 최대 0.0016bp. MXCN1A 0.0001%p, 0.0002bp
- **롤링 IS (MXWO):** 아래 추가 수정으로 6개 시점 모두 선정 일치, 같은 gross 기준 수익 차이 0.004bp 이하

남는 차이 하나 더: 엔진 행 t 의 유니버스는 월말 t 구성이라, 그달 빠지는 종목의 수익이 없고 재편입 종목의 직전 달 수익이 들어간다. 운용은 월말 T 구성을 그대로 들고 가므로 "수정 후 운용" 행이 실제와 같다.

## 추가 수정: 롤링 IS 창 처리 (MXWO)

`mp` 는 48개월로 자른 뒤 lag 를 붙여 규칙 학습과 수익률 행렬에 같이 썼다. 엔진은 규칙만 그렇게 학습하고, 선정·가중 입력 수익률은 전체 이력에 lag 를 붙인 프레임에 규칙을 매핑한다.
직전 값이 창 밖인 종목(재편입, 값 공백)이 `mp` 에서만 그 달 빠지면서 같은 섹터 순위까지 바뀌었다. 팩터 거의 전부(275개 중 270개 이상)의 창 안 수익이 달라지고, 한 달 차이는 최대 5.2%p 다.

**수정:** `factor_analysis.label_window_frames`. lag 는 전체 이력에서 잡고 창 구간만 순위·라벨을 매긴다. 규칙 학습은 그대로 창 안 lag 다 (엔진과 같음). 엔진 코드는 바꾸지 않았다. expanding IS 는 이 경로를 타지 않는다.

## 검증

- pytest 통과 (`test_book_labels_use_as_of_values` 추가). `mp test` 기준 산출물은 의도된 변경으로 갱신 (MXCN1A `meta_data_test`, MXWO `meta_data_test`·`weights_*` 4종)
- 실데이터 `mp` MXCN1A·MXWO 정상 완주, 변경 파일은 9/30 북·이력 12종뿐이고 확인 뒤 커밋본으로 복구
- 창 처리 추가 수정: pytest 340 통과 (`test_window_labels_keep_lag_from_before_window` 추가). `mp test` 추적 산출물 변경 없음. MXCN1A·718708 은 3개 시점 산출물 18개 파일이 수정 전과 byte 단위로 같다. 실제 `mp` 코드는 출력 경로만 scratchpad 로 돌려 실행해 배포 폴더와 `mp_weight_history` 를 건드리지 않았다
- 100개월 "수정 전/후" 는 `mp` 와 같은 함수(`calculate_factor_stats_batch`, `filter_and_label_factors`, `label_book_at_date`, `aggregate_factor_returns`, 선정·가중)를 호출한 scratchpad 스크립트 결과다. 수정 후 경로의 프레임만 캐시한 전체 lag 로 직접 만들었고, 6개 시점 수치는 실제 `mp` 와 소수 6자리까지 같다
